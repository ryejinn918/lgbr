# LG경영연구원 산하 프로젝트 작업일지

**기간:** 2026.07.09 ~ 2026.07.30  
**주제:** 산업 트렌드·리포트 수집 자동화, 보고서 가공, 섹터 인사이트(합의) 도출

업무를 아래 세 갈래로 구분해 정리한다.

1. **밑작업** — 대상 매체·계정·난이도 조사, 데이터·화면·운영 기반
2. **보고서 가공 및 인사이트 도출** — PDF 구조화, 품질감사, Consensus(축·팩·프레임·채움), 온톨로지·외부 조회
3. **수집 자동화** — RSS·브라우저·HTTP 기반 매체 수집, 세션·잡·대시보드 운영

---

## 1. 밑작업

수집·가공이 돌아가기 전에 필요한 조사, 목록 정리, 저장·조회·운영 기반을 깔아 둔 작업이다.

### 1.1 매체·계정·수집 난이도 조사 (07.09~10)

- 주요 뉴스·전문매체 RSS 유무와 피드 URL을 실측하고, 산업 섹터별로 어떤 매체가 붙는지 현황표를 정리함.
- 브라우저만으로 보던 기사 목록을, 서버에서 조회하는 형태로 바꿔 이후 DB·크롤러와 연결할 수 있게 함.
- 섹터 전체 보기에서 여러 매체 기사를 한 목록으로 합쳐 보고, 매체명·발행일을 함께 보이게 함.
- DX·전문매체 등 접근이 어려운 대상을 재검증해 난이도 등급을 다시 매기고, 폐간·부적합 매체는 제외함.
- 회신받은 계정정보와 크롤링 난이도 분류를 한 표로 맞추고, 매체명 불일치·누락을 정리함.  
  → 이후 “무엇을 어떤 방식으로 수집할지”의 기준표가 됨.

### 1.2 데이터·시드·조회 기반 (07.09)

- 매체·소스 등록용 DB 스키마와 초기 시드(upsert)를 구성해, 목록 갱신이 반영되도록 함.
- RSS 실데이터를 적재해 데모가 아닌 실측 피드로 뷰어를 검증함.
- 본문 미리보기 등 검수용 화면을 두어, 수집 품질을 눈으로 확인할 수 있게 함.

### 1.3 통합 운영·보안·원격 접근 기반 (07.22~26, 07.29~30)

- 브라우저 수집·모니터·합의 화면을 한 운영 체계로 묶고, 프로세스 관리·상태 API를 둠.
- 외부 노출 시 UI 인증, API 키 프록시, 터널 경유 미리보기를 허용해 원내·원격에서 같은 화면을 보게 함.
- 수집 모니터와 섹터 합의 화면의 이름·네비를 정리하고, AI/AIDC 등 용어를 맞춤.
- 리포트 목록을 DB에 쌓고, 제공기관·발행일·테마 필터·원문/PDF 다운로드가 되는 카탈로그를 둠.
- 크롤 프로필(검색 조건)과 리포트 테마(다중 라벨)를 분리해, “어떻게 수집했는지”와 “어떤 주제로 쓰는지”를 구분함.
- 매체별 last-run 신선도를 한 보드에 모아, 수집이 멈춘 소스를 바로 보이게 함.
- 외부 에이전트용 읽기 전용 커넥터를 두고, 공개 접속은 OAuth만 허용. PDF는 서명 URL로만 전달함.

### 1.4 밑작업 성과

| 항목 | 결과 |
|------|------|
| 매체 기준 | RSS 실측·난이도·계정·명칭이 정리된 대상 목록 |
| 데이터 | 매체/소스/리포트 목록이 쌓이는 저장·시드 구조 |
| 운영 | 인증·원격 접근·통합 대시보드·프로필/테마 분리 |
| 외부 연동 | OAuth·서명 URL 기반 읽기 전용 조회 |

## 2. 보고서 가공 및 인사이트 도출

수집된 PDF·기사를 구조화하고, 품질을 맞춘 뒤, 섹터별 합의 프레임과 인사이트 초안까지 가는 작업이다.

### 2.1 리포트 PDF 구조화 (07.11~16)

**목적:** 장문 리포트를 “목차–본문 구간” 단위로 쪼개 이후 인용·압축·채움에 쓸 수 있게 함.

- 페이지 병렬로 PDF를 읽어 제목·본문·표·캡션 등 유형을 나누는 실험부터 시작함.
- 구조화 결과를 검수하는 뷰어를 두고, 유형 오분류를 바로잡음.
- 한 번에 처리하던 방식을 **단계형**으로 바꿈.  
  - 제목 / 캡션 / 목차 항목 역할을 분리  
  - 배치 크기를 줄여 표 내용이 조용히 빠지던 문제를 줄임  
  - 캡션과 제목이 겹치는 범위를 명시적으로 한정
- 장문용으로 완전 파싱·검증 흐름을 만들고, 목차(Stage 0) 탐색을 단순·복원력 있게 다듬음.
- 헤딩 트리를 신뢰도·탐색(빔)으로 복구하고, 최종적으로 **목차에 붙이는 방식**으로 정확도를 맞춤.
- 페이지 창 단위 LLM 처리를 병렬화하고, 뷰어에 파싱 정보를 노출해 검수 가능하게 함.
- Physical AI 등 주제 리포트에 대해 개념·관계 온톨로지와 전망 가중 키워드 랭킹 뷰어를 두고, Space·AIDC 카테고리 필터와 배포(인증)까지 맞춤.

### 2.2 리포트 품질감사 (07.23~25, 07.28)

**목적:** Consensus에 넣기 전에 문헌이 섹터 프레임워크·인용에 쓸 만한지 검사함.

- 섹터 프레임워크 기준 품질감사를 두고, 목록에서 검토·배치 실행을 하게 함.
- 감사 문구는 한국어를 필수로 함.
- 감사 과정에서 **인용용 짧은 제목**을 만들고, 목록 검색에도 쓰이게 함. PDF 본문이 없어도 제목만으로 짧은 제목을 채울 수 있게 함.
- FnGuide 외 매체는 감사 정책을 달리 적용(항상 통과 등)해, 수집 경로가 늘어나도 파이프라인이 막히지 않게 함.

### 2.3 Consensus 파이프라인 — 압축 → 축 → 팩 → 프레임 → 채움 (07.23~29)

**목적:** 섹터·테마별로 주요 문헌을 고르고, 합의 프레임을 만들고, 근거 문장으로 채운 뒤 연구원 작업에 넘김.

#### (1) 문서 압축·구간화
- 테마별 문서 압축(compress)과 DB 스키마를 둠.
- 목차 없는 문서도 슬라이스하고, 목차가 있으면 **페이지 번호 계층**으로 자름. 과대 청크는 상한을 둠.
- 압축 본문은 필요할 때 불러오게 하고, 실행이 달라도 같은 문서면 캐시가 맞게 **프롬프트 세트를 고정**함.
- 채팅·압축이 서로를 막지 않도록 비동기·병렬로 돌림.

#### (2) 섹터 축(axis) 검수
- 팩을 고르기 **전에** 섹터 축을 먼저 자르고, **사람이 검수할 때까지 대기**한 뒤 이어서 돌리게 함.
- 실행 중 UI를 잠그고, API가 재시작돼도 작업이 이어지게 함.
- 축·선정 화면을 한흐름으로 합치고, 진행 문구를 명확히 함.

#### (3) 문헌 팩 선정
- 테마마다 LLM으로 문헌 팩을 선정하고, 결과를 저장해 운영 화면에서 보게 함.
- 후보 풀은 **최근 3개월**로 제한.
- 역할을 **주요문헌 / 보조문헌(참고)** 으로 표기하고, 선정 이유에서 자기인용을 막음.
- 팩 스크리닝을 별도 화면으로 두고, 섹터를 URL로 구분해 작업 맥락을 유지함.

#### (4) 프레임·채움·비교
- 프레임 생성 후 근거를 채울 때, 키워드 검색이 아니라 **문서 구간 주소**로 붙이게 바꿔 인용 위치를 안정화함.
- 채워진 프레임이 자체로 완결되게 하고, 최근/이전 실행을 전환해 비교함.
- 비교 UI·운영 API, LGERI용 비교 채팅(저장·시의성 있는 프롬프트)을 둠. 채팅 쪽 웹검색은 품질을 위해 제거함.
- 출력을 LG 토픽 어투에 맞추고, 인용은 **사람용 출처 각주** 형식으로 정리함.
- 프레임/합의 결과를 짧게 복사하는 기능을 두고, 편집 팁을 안내함.
- 합의 평가용 개요 뷰를 실험했다가, UI 준비가 될 때까지는 숨김.

### 2.4 인사이트 활용·외부 드래프팅 (07.23, 07.30)

- Google News 검색 결과를 짧은 TTL로 캐시해, 비교·보강 시 반복 호출을 줄임(이후 채팅 웹검색은 정책상 제거).
- 합의·문헌을 산업 트렌드 초안 작성용으로 조회하도록 외부 커넥터를 단순화함(`합의 조회` 중심).

### 2.5 보고서 가공·인사이트 성과

| 단계 | 결과 |
|------|------|
| 구조화 | 장문 PDF → 목차·본문 구간, 검수 뷰어, 주제 온톨로지 |
| 품질 | 섹터 프레임워크 감사, 한국어 코멘트, 인용 짧은 제목 |
| Consensus | 축 사람 검수 → 팩 선정 → 프레임 → 구간 주소 채움 |
| 활용 | 비교 채팅·복사, LG 어투·각주, 외부 드래프팅 조회 |

## 3. 수집 자동화

대상 매체에서 리포트·기사를 주기적으로 가져오고, 실패해도 운영자가 상태를 보고 재개할 수 있게 한 작업이다.

### 3.1 초기 RSS·뉴스 수집 (07.09)

- 전자신문·NASDAQ 등 RSS를 섹터별로 모아 보는 데모에서 출발.
- 매체별 프록시·요청 헤더를 맞추고, RSS 크롤러로 실데이터를 적재함.
- 정치·정책 등 범위 밖 피드는 시드에서 제외함.

### 3.2 Fnguide 브라우저 수집·세션 운영 (07.22~23)

- Fnguide 라이브러리 조회·스캔과, 로컬 브라우저에 가까운 환경으로 로그인 세션을 유지하는 수집을 구성함.
- 세션 이력·모니터, 수동 실행, **오류 시 자동 재시작을 막고** DB에서 해제한 뒤에만 다시 돌리게 함(이중 상태·fail-closed).
- API로만 크롤을 시작하게 하고, 필요 시 원격 브라우저 제어를 둠.
- 데이터센터(이후 AI/AIDC) 수집 잡, 종료 시 프로세스 정리, 이벤트 로그·로그인 진단 강화.
- 다운로드 파일을 실행 단위 폴더로 나누고, 목록 리포트를 DB에 쌓음.
- 검색 프로필 편집, Physical AI 수집 모드, 필터 대기·실패 캡처 강화.
- 세션별 활동 타임라인으로 “지금 뭐가 돌았는지”를 추적함.

### 3.3 검색·기간·섹터 확장 (07.28~29)

- FnGuide에 신규 검색 섹터와 **다중 키워드·기간** 크롤을 추가함.
- 검색 프로필 기본 조회 기간을 **최근 3개월**로 둠.
- 실행 상태·last-run·필터 요약을 FnGuide 모드에만 묶이게 해, 다른 매체 잡과 섞이지 않게 함.

### 3.4 ARG·기사 본문 수집 (07.26, 07.29)

- ARG 피드 목록을 찾고, 수집 모니터 화면 구조를 맞춤.
- 기본으로 최근 3개월 피드를 모으고, 본문 가져오기를 붙임.
- 피드와 본문을 **한 매체 전용 잡**으로 묶어 동시 충돌을 막고, 본문 수집 상태를 필터 칩으로 보게 함.

### 3.5 컨설팅·인사이트 매체 HTTP 수집 (07.29)

목록을 돌리면서 PDF를 받는 방식(list-while-download)으로 확장하고, HTTP 요청 방식을 통일함.

| 매체 | 내용 |
|------|------|
| PwC → 삼일 Insights | 국내/글로벌 카탈로그, 페이지 수, 목록 정리 |
| Accenture US | Research Report 목록·다운로드, 항목 간 대기 |
| KPMG US Insights | 동일 패턴 검색·다운로드 |
| EY US Insights | 동일 패턴 |
| Deloitte US Insights | 다중 쿼리 프로필까지 지원 |

- 공통 매체 소스 등록부를 두고, 항목 간 delay를 설정할 수 있게 함.
- 매체별 실행 배지·칩을 그 매체 세션에만 묶고, FnGuide 전용 타임라인은 걷어 냄.
- 운영 화면에 **매체 × 주간 커버리지**를 두어, 어느 주·어느 매체가 비었는지 보이게 함.

### 3.6 수집 자동화 성과

| 항목 | 결과 |
|------|------|
| 경로 | RSS → 브라우저 세션(Fnguide) → HTTP 목록·다운로드(다수 인사이트) |
| 안전 | 오류 시 재시작 차단, 매체별 exclusive 잡, 상태·로그 |
| 범위 | FnGuide 섹터·기간, ARG 본문, 삼일·Accenture·KPMG·EY·Deloitte |
| 가시성 | 세션 타임라인, 커버리지 그래프, 전 매체 last-run 보드 |

## 한 줄 요약

- **밑작업:** “누구를·어떻게” 수집할지 기준과, 저장·인증·운영 화면을 만듦.
